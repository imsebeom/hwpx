# KS X 6101:2024 (OWPML) 대조 메모

HWPX의 국가표준 원문(414쪽, 2024-10-30 개정)을 스킬 관점에서 정독하고 한컴 실물과 대조한 결과다. 표준 원문은 저작권 보호 대상이라 여기에는 **조항 번호와 기술적 사실만** 적는다. 열람: e나라표준인증(standard.go.kr).

핵심 전제 하나. **표준 문서와 한컴 실제 구현은 여러 곳에서 다르다.** 한글에서 열려야 하므로 실무 기준은 언제나 실물이고, 표준은 (1) 우리가 실측으로 얻은 규칙의 근거, (2) 아직 안 쓰는 기능의 사전, (3) 검증 규칙의 출처로 쓴다.

---

## 1. 표준과 한컴 구현이 어긋나는 지점

편집 중 판단이 갈릴 때 이 표를 먼저 본다. **실물 열이 정답이다.**

| 항목 | 표준 규정 | 한컴 실물 | 스킬 |
|------|-----------|-----------|------|
| 네임스페이스 | `owpml.org/owpml/2024/{head,body,paragraph,core,version,master-page,history}` (§5.2) | `hancom.co.kr/hwpml/2011/*` + `2016/paragraph` | 실물 사용 (옳음) |
| 본문 루트 접두사 | `hb`(body), `hs`는 history (§5.2, §10.1) | `hs:sec` = section | 실물 사용 (옳음) |
| version.xml 루트 | 요소명 `version` (부속서 B) | `<hv:HCFVersion>` | 실물 사용 |
| version 속성 | `tagetApplication` (오타가 스키마에 `use="required"`로 확정) | 동일한 오타 사용 | **고치지 말 것** |
| version `micro` 타입 | `xs:nonPositiveInteger`(0 이하) — 표준 오류 | `micro="1"` | 실물 사용 |
| content.hpf item | `@isEmbedded` + `@sub-path` 필수 (§8.4.2) | `isEmbeded`(d 1개), `sub-path` 없음 | 실물 사용 (옳음) |
| header.xml 글꼴 | — | `hh:font@isEmbedded`(d 2개) | 위치마다 철자가 다르다 |
| paraPr 자식 순서 | align → heading → breakSetting → margin → lineSpacing → border → **autoSpacing** (부속서 C) | align → heading → breakSetting → **autoSpacing** → margin → lineSpacing → border | 실물 순서를 따를 것 |
| secPr 자식 순서 | **startNum** → grid → … (부속서 C) | **grid** → startNum → visibility → lineNumberShape → pagePr → footNotePr → endNotePr → pageBorderFill | 실물 순서 (스킬 주석과 일치) |
| head 필수 자식 | beginNum, refList, trackchangeConfig (부속서 C) | trackchangeConfig 없음 | 실물에 없어도 정상 |
| margin 하위 접두사 | `hh:intent` 등 (§7.2.5) | **`hc:intent`** | 실물 사용 |
| pic 내부 접두사 | `hp:img`, `hp:transMatrix`, `hp:pt0` (§10.9.6 샘플) | **`hc:img`, `hc:transMatrix`, `hc:pt0`** | 실물 사용 (옳음) |
| borderFill 선 굵기 | `LineWidth`는 xs:float 열거 (표 8) — 본문은 "단위 mm" | `width="0.1 mm"` 문자열 | 실물 사용 |
| 색상 | `#[0-9A-Fa-f]{6}` (§7.4) | `shadeColor="none"`, `faceColor="none"` 관용 | 실물 사용 |

### linesegarray는 규격 외 요소다

부속서 E의 `PType`(문단)은 `<xs:sequence>`로 **`run`만** 자식으로 가진다. `linesegarray`/`lineseg`는 부속서 B~I 스키마 전체에 정의가 없고 본문 샘플(§10.7.5, §10.7.12)에만 등장한다.

→ 한컴이 넣는 줄바꿈 캐시는 스키마에 없는 요소이므로, 편집 후 **제거하는 것이 표준 적합성 면에서 정확한 처리**다(Critical Rule 17, `hwpx_modifier`·`hwpx_form_filler`의 자동 제거). 낡은 lineseg가 남으면 한글이 해당 문단부터 내용을 조용히 버린다 — [troubleshooting.md](troubleshooting.md) 참조.

## 2. 스킬 규칙의 표준 근거

| 스킬 규칙 | 근거 조항 | 내용 |
|-----------|-----------|------|
| Critical Rule 2 (secPr 필수) | §10.2, §10.6 | 구역은 1개 이상, 한 구역은 1개 이상 문단 필수 |
| Critical Rule 3 (mimetype STORED) | §8.2, §8.3 | OCF 컨테이너 + version.xml 필수 |
| Critical Rule 24 (charPr borderFillIDRef) | 표 46 | 이 속성은 **글자 테두리를 쓸 때만** 존재하는 조건부 속성. 테두리 있는 borderFill을 가리키면 글자마다 네모가 그려진다 |
| Critical Rule 25 (styleIDRef="0") | §9.3.9 샘플 42 | 표준 기본 스타일 21종 중 id 0이 "바탕글"(Normal) |
| Critical Rule 33 (표 행 삭제 3종 보정) | 표 194·202·204 | `rowCnt`(행 개수), `cellAddr@rowAddr`(0부터 증가), `cellSz@height`(HWPUNIT) |
| 빈 셀에 빈 문단 유지 | §11.1.2 | subList는 내용이 없어도 빈 `<p>`를 반드시 가져야 한다 |
| 줄간격 160% 기본 | §3.38 | 표준 바탕글: 함초롬바탕 10pt, 장평 100%, 자간 0%, 줄간격 160%, 양쪽 정렬 |

### Critical Rule 32(charPr 목록 끝에만 append)의 위치

스키마상 `charPrIDRef`는 `xs:nonNegativeInteger`로 **id 참조**처럼 정의되어 있다. 그러나 한컴 구현은 **목록 내 물리적 순서(0-based 인덱스)** 로 해석한다 — 2026-07-09 실측(중간 삽입 시 문서 전체 서식이 한 칸씩 밀림). 표준으로는 설명되지 않는 구현 동작이므로 규칙 32는 실측 근거로 유지한다.

## 3. 아직 안 쓰는 표준 기능 (필요할 때 꺼내 쓸 것)

### 쪽 나눔 제어
- `tbl@pageBreak` = `NONE`(표를 나누지 않음) / `TABLE`(셀은 안 나눔) / `CELL`(기본) — 표 194
- `tbl@repeatHeader="1"` — 나뉜 쪽에서 제목 행 반복
- `paraPr > breakSetting@keepLines`(문단 보호), `@keepWithNext`(다음 문단과 함께), `@pageBreakBefore`, `@widowOrphan`(외톨이줄) — 표 78

### 표
- `cellzone` — 사각 영역에 테두리/배경 일괄 지정 (§10.9.3.3)
- `tc@name` — 셀 필드 이름. 좌표 대신 이름으로 셀을 지목 (표 200)
- `label` — 라벨 용지(이름표) 배치 (§10.9.3.5)

### 본문
- `caption` + `autoNum numType="PICTURE|TABLE"` — 표·그림 캡션과 자동 번호 (§10.9.2.5)
- `markpenBegin`/`markpenEnd` — 형광펜 (§10.8.2)
- `nbSpace`(묶음 빈칸), `fwSpace`(고정폭 빈칸) — 표 182
- `pageNum pos="BOTTOM_CENTER" formatType="DIGIT" sideChar="-"` — 쪽 번호 (§10.7.10)
- `pageHiding` — 특정 쪽의 머리말/꼬리말/쪽번호 감추기 (§10.7.9)
- `beginNum` — 페이지·각주·미주·그림·표·수식 시작 번호 (§9.2.2)

### 문서 수준
- content.hpf 메타데이터: `dc:title`, `dc:creator`, `dc:subject`, `dc:description`, `dc:publisher`, `dc:language`, `<meta name="CreateDate|ModifiedDate|Keywords">` (표 10)
- `docOption > licensemark` — 저작권 표시(상업적 이용 제한 등) (§9.2.7.2)

### 수식 (부속서 I)
`<hp:equation><hp:script>` 안에 스크립트를 넣는다. `Equation Version 60`. 항 구분은 공백, 여러 항 묶기는 `{ }`, **9자를 넘는 항은 자동 분리되므로 `"…"`로 감싼다**. 기본 이탤릭이고 `rm`(로만) `it` `bold`로 전환, 공백은 `~` 또는 `` ` ``, 줄바꿈은 `#`.

## 4. 검증에 쓸 수 있는 조항

`verify_hwpx.py`·`validate.py` 확장 후보다. 괄호 안은 근거.

- [x] version.xml은 **압축·암호화 금지** (§8.3) — `build_hwpx.py`에 반영 완료(ZIP_STORED + validate 검사)
- [ ] fontfaces·charProperties·paraProperties의 `itemCnt`는 1 이상이고 실제 자식 수와 일치 (§9.3.2.1, §9.3.4.1)
- [ ] `font@isEmbedded`가 참인데 `binaryItemIDRef`가 무효하면 오류 (§9.3.2.2.2)
- [ ] 모든 subList는 `<p>` 1개 이상 (§11.1.2)
- [ ] 텍스트는 유니코드 **NFC 정규화** 필수 (§5.3) — macOS 경유 NFD 자모 분리 문자열이 들어오면 검색이 깨진다
- [ ] `META-INF/manifest.xml`에 `encryption-data`가 있으면 암호화 문서 → 편집 불가 안내 (§15)
- [ ] `META-INF/signatures.xml`이 있으면 전자서명 문서 → 편집 시 서명 무효 경고 (§16)

## 5. 편집 시 주의

- **switch/case/default**(§17): 차트 등은 `<hp:switch>` 안에 `case`(chart)와 `default`(ole) **두 벌**로 저장된다. 전역 치환은 양쪽을 함께 바꾸지만, lxml로 한쪽 노드만 고치면 뷰어에 따라 다른 내용이 보인다.
- **run이 담을 수 있는 객체는 30종**(표 99): tbl·pic 외에 container(묶음), ole, equation, textart, chart, video, 양식 객체(btn/edit/comboBox…) 등. 외부 양식을 편집할 때 모르는 요소는 보존한다.
- **적합성 레벨**(§4.4): 문서 요소를 SP0~SP3으로 나눠 리딩 시스템 지원 수준을 0~3단계로 정의한다. 우리가 만드는 문서는 표·그림·머리말 수준이라 실무상 문제되지 않는다.

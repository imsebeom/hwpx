# 조판 일치율 채점 (2026-10-17)

rhwp 엔진이 한/글 2024 와 얼마나 같게 조판하는지 한 번에 잰다. 회귀 시험(`../linebreak/svghash.mjs`)이 「직전 엔진과 같은가」를 본다면, 이것은 「한/글과 같은가」를 본다.

## 돌리는 법

```bash
python oracle_driver.py            # 한/글 정답본 만들기(354개 약 25분, 이어 돌리기 됨). 목록 기본값 ../linebreak/results/reg_corpus_1014.txt
node score.mjs out/score           # 채점(약 25초) → scoreboard.json, mismatches.jsonl
python classify.py out/score       # 불일치 원인 분류 → causes.json
```

`out/` 은 실사용 문서 사본과 정답본이라 git 에서 뺀다. 엔진을 바꾼 뒤에는 `node score.mjs` 만 다시 돌리면 된다(정답본은 그대로).

## 방법

- 정답: 한/글로 열어 **쪽수를 먼저 물은 뒤** HWPX 로 다시 저장한 파일의 `<hp:lineseg textpos, vertpos>`. 열기는 `Open` 반환값과 `hwp.Path` 로 확인한다(열기 실패 문서는 건너뜀).
- rhwp: 같은 정답본에서 줄 배치만 지운 사본을 연 뒤 `getLineStarts(목록, 문단)`. 내용과 구조가 같아 차이는 조판 차이다. hwp 원본도 한/글이 저장한 HWPX 를 거친다. 글꼴은 에디터처럼 설치 글꼴 파일에서 폭을 등록한다.
- 지표: 본문 문단 줄바꿈, 칸 문단 줄바꿈(각각 여러 줄 문단만의 값도), 문서 쪽수, 본문 문단의 쪽. 같은 명령 두 번이 같은 결과를 낸다.

## 확인한 전제 (probe_*.mjs)

| 전제 | 결과 |
|---|---|
| rhwp 는 줄 배치가 적힌 문서를 어떻게 여나 | 적힌 값을 그대로 믿고 그대로 내보낸다 → 반드시 지우고 넣는다(`probe_premise.mjs`) |
| 지운 문서를 `exportHwpx` 하면 계산값이 나오나 | 줄 배치를 아예 쓰지 않는다. `reflowLinesegs()` 도 0문단 → 내보내기로는 못 잰다 |
| `getLineStarts` 가 한/글 textpos 와 같은 눈금인가 | 같다(시험 문서 3개 여러 줄 문단 모두 일치, `probe_linestarts.mjs`) |
| 칸 목록 번호가 XML 과 대응하나 | 부모가 `hp:tc` 인 subList 순서와 1:1(120개 중 118개, 어긋난 2개는 칸 비교에서 뺌, `probe_lists.mjs`) |
| 표 안 표의 칸 | `getLineStarts` 가 언제나 `[]`(270칸 중 269칸, 쪽을 다 그려도 같음) → 측정 불가로 따로 센다(`probe_lazy.mjs`) |
